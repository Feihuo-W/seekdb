# MiniVectorDB 性能优化日志

## 测量方法

- 工具：`minivectordb/tools/bench.py`（仓库内，可复现）。
- 负载：官方 benchmark 形状——10,000 行 × 128 维向量，每批 100 行写入并提交；
  随后 1,000 次 TopK 查询，K=10，其中一半带 `category` 等值过滤。
- 轮次：各指标取多轮中位数；每轮独立数据目录。
- 指标口径：
  - `T_write`：全部批次请求 + 结果输出 + 持久化的墙钟时间。
  - `T_query`：全部查询请求处理与结果输出的墙钟时间（不含装载/预热）。
  - `B`：`/proc/<pid>/io` 的 `read_bytes + write_bytes` 增量（块设备 I/O 近似；
    平台正式口径为 cgroup v2 `io.stat`，含页缓存写回）。
  - `M`：`/proc/<pid>/status` 的 `VmHWM`（峰值 RSS；平台正式口径为 cgroup
    `memory.peak`，含文件页缓存，数值会更大）。
  - `Recall@10`：每轮抽样查询（含有过滤/无过滤）与 Python 暴力真值比较。
  - 每轮校验：返回行数=K、无重复、满足过滤、重启后数据仍在。
- 环境：WSL2 Linux x86_64，16 核，g++ 9.4 `-O3`，CPU 支持 AVX2/FMA。
- **噪声说明**：本机 `fdatasync` 抖动大（写入 1.9–3.6s），且宿主负载随时间变化，
  跨时段单独跑分不可比。因此**版本效果以同会话 A/B 为准**：把基线二进制与优化二进制
  紧邻交替运行相同轮次，抵消漂移。微基准（`/tmp/micro.py`，单会话内连续测多种查询）
  用于定位瓶颈。

## 权威对比：v0 vs v3（同会话 A/B，各 5 轮）

| 指标 | v0 基线 | v3 优化 | 变化 |
| --- | --- | --- | --- |
| T_query 中位 (ms) | 909.44 | 589.73 | **−35.2%** |
| T_write 中位 (ms) | 2290.49 | 2330.97 | +1.8%（噪声内，持平） |
| B 中位 (bytes) | 5,971,968 | 5,971,968 | 持平 |
| M 中位 (kB) | 12,056 | 11,884 | −1.4%（持平） |
| Recall@10 | 1.000 | 1.000 | 持平 |
| 正确性/持久性 | 通过 | 通过 | 持平 |

v0 五轮查询：1203.6 / 1338.4 / 892.7 / 858.3 / 909.4 ms
v3 五轮查询：542.6 / 589.7 / 587.0 / 869.2 / 707.7 ms

结论：查询耗时下降约三分之一，写入/I/O/内存不变（写入受 `fdatasync` 支配，
I/O 由数据量决定，均未因优化改变）；召回率与正确性保持 1.0/通过。

## 瓶颈定位（微基准，单会话）

| 查询类型 | v0/v1 | v2 | v3 |
| --- | --- | --- | --- |
| 未过滤 TopK（ORDER BY distance LIMIT 10） | 0.984ms | 0.692ms | 0.721ms |
| 过滤扫描（WHERE category，无距离） | 0.588ms | 0.340ms | 0.281ms |
| 过滤后 TopK | 0.491ms | 0.390ms | 0.402ms |

未过滤 TopK 需顺序读取全部 ~5MB 向量，属**内存带宽受限**：
- v1 的计算优化（少一次 sqrt、SIMD 多累加器、定长偏移）降低计算占比，但在带宽受限处单独看不出收益；
- v2 把 `std::map` 逐节点跳转改为扁平 `vector` 顺序遍历，显著提升带宽利用（−30%）；
- v3 去掉热路径每行 `ColAt` 调用，收益被噪声淹没（中性），但代码更直接。

## 各版本改动明细

### v1（`12ceef850`）计算路径
- 行内布局改为「定长列（BIGINT/VECTOR）在前 + VARCHAR 长度表 + VARCHAR 字节」，
  使向量列偏移与字符串长度无关，扫描无需逐列行走（`Schema::ComputeLayout`）。
- 距离比较改用**平方距离**（单调等价），扫描期不再每行 `sqrt`，仅最终 K 个输出开方。
- AVX2/FMA 由单累加器改为 **4 累加器**，打破 FMA 依赖链，提升吞吐。
- 注意：行格式变更，旧 `/data` 不兼容（提测每次从空目录开始，无影响）。

### v2（`1d4cae9c5`）扫描结构
- `TableState` 增加扁平 `scan`（pk 有序的 `(pk, RowRef)` 数组）+ `scan_dirty` 标志；
  无事务 overlay 时按数组顺序扫描，提交/压缩后置脏、惰性重建。
- 事务内仍走 map+overlay 归并，保证读己之写正确。

### v3（`347894135`）热路径取址
- TopK 循环预先取出 `vec_off = fixed_off[dist_col]`、查询向量指针与维度，
  每行直接 `v.p + vec_off` 取向量，省去 `ColAt` 调用与边界检查。

## 后续方向（未实施）
- 列式向量存储（向量连续成块）进一步逼近带宽上限；
- IVF 近似索引降低 ann 模式读取量（exact 模式仍需全扫描，平台默认 exact）；
- 写入路径受 `fdatasync` 支配，评测机若 fsync 更快则写入占比自然下降。
